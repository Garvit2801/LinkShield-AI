# Cloud setup — step by step

## Prerequisites

- Google Cloud account/project, billing enabled, owner/project service access
- `gcloud`, Terraform >=1.5, Docker for local worker, ADC (application default credentials)
- Region `us-central1` recommended because Terraform BigQuery dataset is `US` multi-region

## Quick deploy with only the Editor role

`./deploy-gcp.sh <project-id> [region]` deploys both services with plain gcloud commands and never changes IAM policies, so a project Editor can run it. Region defaults to `asia-south1`.

- Both services run as the project's default compute service account (it has Editor in projects without an organization).
- The sandbox is a private Cloud Run service; the API reaches it with an identity token plus the shared sandbox token, which is a plain environment variable.
- There is no Firestore, so history and rate limits live in memory and the API is capped at one instance.
- The website is deployed private. Open it in a browser through an authenticated local proxy:
  `gcloud run services proxy linkshield --region asia-south1 --port 8081`, then visit http://localhost:8081.
- To make it public: `gcloud run services update linkshield --region asia-south1 --no-invoker-iam-check`, or a project Owner adds `allUsers` as `roles/run.invoker`.

The Terraform setup below is the locked-down version (own service accounts, Secret Manager, Firestore) and needs an Owner.

## Build API cloud resources

```bash
gcloud auth login
gcloud auth application-default login
gcloud config set project YOUR_PROJECT_ID
./deploy.sh YOUR_PROJECT_ID us-central1
```

Terraform provisions API service account, Artifact Registry, Cloud Run, enabled APIs, BigQuery datasets for legacy and new scans, Pub/Sub topic, a private GCS bucket and IAM grants. Terraform initially applies with a placeholder Cloud Run image to create the artifact registry, then builds the final application image, then deploys it. Both operations cost money depending on usage.

## Firestore and Firebase

1. In Firebase Console, attach Firebase to your Google Cloud project and enable **Authentication > Sign-in method > Google**; configure the Cloud Run domain in authorized domains.
2. In Google Cloud Console, create the (default) **Firestore Native** database, or set `create_firestore_database=true` in Terraform **only when no database exists**.
3. Add `-var enable_firestore=true -var firebase_api_key='...' -var firebase_auth_domain='...' -var firebase_app_id='...'` to Terraform `apply` on the deployment (or in your own safe `terraform.tfvars`). Do not keep secrets in source control. Firebase API key identifies a client app and is not a server secret; configure API restrictions per Firebase guidance.
4. Make sure the Cloud Run app is accessible over HTTPS. Firebase sign-in frontend uses the Google sign-in popup. Check `/api/v1/capabilities`.

## Enable Gemini and Web Risk

The backend uses service account ADC, the Google Gen AI SDK with `vertexai=True`, the Gemini model selected by `GEMINI_MODEL` (default `gemini-2.5-flash`) and Google Web Risk Lookup v1. Verify project quotas, model availability, service accounts and billing. A URL not on a threat list is not automatically safe.

## Sandbox worker in Google Cloud

`deploy.sh` builds `sandbox/Dockerfile` and Terraform deploys it as a second Cloud Run service, `linkshield-sandbox`:

- It runs as its own service account, which has no project roles, so a compromised worker holds no usable cloud credentials.
- Only the API's service account has `run.invoker` on it. The API sends a Google identity token (`X-Serverless-Authorization`) plus the worker's own bearer token.
- The bearer token is generated by Terraform and kept in Secret Manager. It also appears in Terraform state, so keep the state in a private bucket.

This is isolation by identity and service boundary. It is not a per-scan disposable VM, and Cloud Run egress still reaches the public internet. Read `SECURITY.md` before sending hostile traffic through it. To use a dedicated VM instead, pass `-var sandbox_url=... -var sandbox_token=...` and leave `sandbox_image` unset.

## Sign-in, bots and lookups

- **Sign-in** is required by default (`auth_required=true`). Pass `firebase_api_key`, `firebase_auth_domain` and `firebase_app_id`, and enable both **Google** and **Anonymous** providers in Firebase Authentication. Anonymous is the guest mode; a guest who signs in with Google keeps their history.
- **VirusTotal**: `-var virustotal_api_key=...`. The free tier allows 4 lookups a minute.
- **Telegram**: create a bot with @BotFather, pass `-var telegram_bot_token=... -var telegram_bot_username=...`, then run the `setWebhook` command that `deploy.sh` prints.
- **WhatsApp**: needs a WhatsApp Business account on the Meta Cloud API. Pass `whatsapp_token`, `whatsapp_app_secret` and `whatsapp_display_number`, then set the webhook URL and verify token that `deploy.sh` prints.
- **Shared rate limit**: with `enable_firestore=true` the per-person limit is kept in Firestore (`linkshield_limits`). Add a TTL policy on its `expires_at` field to clear idle counters.

## Observability

BigQuery scan log: `<project>.linkshield.scan_events`. No raw URLs are stored in telemetry. Pub/Sub topic: `projects/<project>/topics/linkshield-scan-events`. Subscribe a downstream processor if needed; the app publishes the event but does not create a consumer automatically. Screenshots in `<project>-linkshield-evidence` are private and automatically deleted after one day. Legacy misinformation trends live under `<project>.linkshield.claims_log`.

## Production checklist

- [ ] Enforce Firebase ID token authentication and global rate limits
- [ ] Add budget caps, monitoring, alerting and a WAF
- [ ] Review the sandbox service against `SECURITY.md`; add enforced egress controls before hostile traffic
- [ ] Keep Terraform state private (it contains the generated tokens)
- [ ] Review GDPR/DPDP privacy obligations and enable appropriate retention/deletion
- [ ] Validate against representative malicious/benign URLs under an authorized test program
- [ ] Confirm Web Risk quotas and Gemini costs
- [ ] Run unit, security and integration tests in the target environment
